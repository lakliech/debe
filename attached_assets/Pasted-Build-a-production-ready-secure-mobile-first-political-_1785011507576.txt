Build a production-ready, secure, mobile-first political campaign management platform for a Kenyan presidential campaign in the 2027 General Election. The platform should be called Ushindi 2027 and should operate as a complete national campaign management, volunteer mobilisation, crowdfunding, communications, field operations and polling-station vote tally system.

The platform must be designed for Kenya’s administrative and electoral structure:

National → County → Constituency → Ward → Polling Centre → Polling Station.

Use a modern, scalable architecture. Build the web application using Next.js with TypeScript, Tailwind CSS and a clean professional user interface. Use PostgreSQL with Prisma ORM for the database. Use secure server-side APIs, role-based access control, audit logs, encryption, two-factor authentication support and configurable integrations for M-Pesa Daraja, SMS, email, WhatsApp Business, USSD, cloud storage and mapping services.

Create a fully functional application, not merely static mock-ups. Where external credentials are unavailable, implement working sandbox adapters, configuration screens and clear environment-variable placeholders.

Polling-station vote tally system

Create a secure campaign Parallel Results Management System based on official polling-station result forms submitted by authorised campaign agents.

The system must recognise that presidential votes are counted and recorded at polling-station level. However, the application must clearly distinguish the campaign’s independently collected and verified tally from the official results declared by the constitutionally authorised electoral body.

Never label campaign totals as official national election results.

Automatic validation rules

Before accepting a submission, validate that:

* Candidate vote totals equal total valid votes.
* Valid votes plus rejected ballots reconcile to total votes cast where applicable.
* Ballot-accounting figures reconcile or are clearly flagged.
* Votes do not exceed registered voters.
* Candidate names match the configured election.
* The polling-station code is valid.
* The submitting user is assigned to that polling station.
* Required form images are attached.
* Duplicate submissions are detected.
* Images meet minimum readability requirements.
* Unusual values are flagged.

Do not automatically reject a legally valid result solely because of an arithmetic inconsistency. Place inconsistent submissions in an exception workflow for human verification.

Verification workflow

Implement this workflow:

Agent submission → Automatic validation → Polling-centre review → Constituency verification → County verification where required → National verification → Legal review for disputed submissions → Verified tally.

Every submission should have one of these statuses:

* Not reported.
* Draft.
* Submitted.
* Synchronising.
* Validation failed.
* Pending verification.
* Image unclear.
* Duplicate suspected.
* Arithmetic exception.
* Agent dispute.
* Verified.
* Legally escalated.
* Superseded.
* Rejected with reason.

A verifier must compare entered figures against the uploaded official form.

Allow a second verifier for sensitive or disputed stations.

Every correction must preserve:

* Original value.
* Corrected value.
* User making the correction.
* Date and time.
* Reason.
* Supporting evidence.
* Approver.
