🟡 PARTIALLY FIXED — Needs Attention
1.  Tally Read vs. Compute Inconsistency
File: tally.ts
POST /compute filters on both resultSubmissionsTable.status ∈ TALLY_ELIGIBLE_STATUSES and eq(submissionCandidateVotesTable.isVerified, true).
But GET /national, /county, /constituency, /ward only filter on resultSubmissionsTable.status ∈ TALLY_ELIGIBLE_STATUSES — they do not filter submissionCandidateVotesTable.isVerified.
Risk: If isVerified ever desyncs from status (race condition, manual DB edit, migration error), the live dashboard will show different numbers than the computed snapshot.
Fix: Add eq(submissionCandidateVotesTable.isVerified, true) to all tally GET aggregation queries, or drop the isVerified filter from compute and rely solely on TALLY_ELIGIBLE_STATUSES.
----
2.  Agent Replacement Approval Still Doesn't Execute the Swap
File: pollingAgentsMgmt.ts — PATCH /replacements/:rid/approve
The endpoint updates agentReplacementsTable.status → "approved" but never updates:
•  pollingAgentsTable.pollingStationId for the replacement agent
•  campaignStationProfilesTable.primaryAgentId / backupAgentId
•  The original agent's status
The replacement exists as a paper trail only. The operational assignment doesn't change.
Fix: On approval, run a transaction that:
3.  Sets original agent status = "replaced" and clears pollingStationId
4.  Sets replacement agent pollingStationId = replacement.pollingStationId
5.  Updates campaignStationProfilesTable primary/backup assignment

9. TALLY_ELIGIBLE_STATUSES Type Cast
File: tally.ts — multiple instances of:
inArray(resultSubmissionsTable.status, TALLY_ELIGIBLE_STATUSES as string[])
If TALLY_ELIGIBLE_STATUSES is already a string[], the cast is harmless. But if it's defined as a readonly tuple or const assertion, Drizzle's inArray may not accept it without the cast. The cast itself is a code smell — better to define it as a proper array type.
