# Replit Agent Prompt: Election Day Logistics & Security Command Center

Build a real-time election day logistics and security command center for Debe. This is a mission-critical module used on election day to track thousands of polling agents, vehicles, and security incidents across all 47 Kenyan counties.

## Database Schema (lib/db/src/schema/logistics.ts)

Create 5 tables:

1. **vehiclesTable** — Campaign vehicle fleet
   - id, tenantId, registrationNumber, make, model, capacity, vehicleType
   - assignedDriverId, assignedCountyId, assignedConstituencyId
   - status ("available" | "deployed" | "maintenance" | "broken_down")
   - gpsDeviceId, lastGpsLat, lastGpsLon, lastGpsAt
   - fuelCapacityLiters, currentFuelLevel
   - createdAt, updatedAt

2. **transportAssignmentsTable** — Election day transport plans
   - id, tenantId, electionId, vehicleId, driverId
   - origin/destination (countyId + text description)
   - passengerAgentIds (JSONB array)
   - planned/actual departure and arrival timestamps
   - status ("scheduled" | "en_route" | "arrived" | "delayed" | "cancelled")
   - delayReason, fuelIssuedLiters, fuelCostKes

3. **agentCheckInsTable** — GPS check-ins throughout election day
   - id, tenantId, electionId, agentId, pollingStationId
   - checkInType ("arrival" | "setup_complete" | "voting_started" | "voting_ended" | "counting_started" | "results_submitted" | "departure")
   - gpsLat, gpsLon, gpsAccuracy, photoUrl
   - distanceFromStation, isWithinGeofence
   - deviceId, source

4. **securityIncidentsTable** — Incident reporting and tracking
   - id, tenantId, electionId, reportedByAgentId, reportedByUserId
   - countyId, constituencyId, pollingStationId, gpsLat, gpsLon
   - incidentType ("violence" | "intimidation" | "vote_buying" | "ballot_stuffing" | "agent_exclusion" | "voter_suppression" | "property_damage" | "injury" | "death" | "other")
   - severity ("low" | "medium" | "high" | "critical")
   - title, description, photoUrls, videoUrls
   - status ("reported" | "verified" | "escalated" | "resolved" | "false_alarm")
   - assignedTo, escalationLevel, resolutionNotes, resolvedAt, resolvedBy
   - isPanicButton, panicButtonAcknowledgedAt, panicButtonAcknowledgedBy

5. **panicAlertsTable** — Fast-access panic button alerts
   - id, tenantId, electionId, agentId, pollingStationId
   - gpsLat, gpsLon, status ("active" | "acknowledged" | "resolved" | "false_alarm")
   - acknowledgedAt, acknowledgedBy, resolvedAt, notes

Add indexes on all foreign keys and frequently queried columns (status, createdAt, agentId, electionId).

1. Tap and hold red button for 3 seconds (prevents accidental trigger)

## Business Logic

**Missing Agent Detection:**
- Every 30 minutes, compare assigned agents vs latest check-in
- Expected check-in windows: arrival by 6 AM, voting start by 9 AM, voting end by 5 PM, results by 9 PM
- If window missed by &gt;30 min, flag as missing
- Auto-SMS/WhatsApp to agent: "You have not checked in. Please confirm your status."

**Geofence Validation:**
- On check-in, compute haversine distance between agent GPS and polling station coordinates
- isWithinGeofence = distance &lt;= 200 meters
- If false, flag as "geofence_violation" but still accept check-in
- Alert field officer

**Transport Delay Detection:**
- If actual departure &gt;15 min after planned, mark delayed
- If en_route and ETA passed by &gt;30 min, auto-alert transport coordinator
- Compute ETA from GPS speed + distance to destination

**Incident Escalation:**
- Level 1: Field officer
- Level 2: County coordinator
- Level 3: Regional director
- Level 4: National security chief
- Level 5: Campaign manager + legal team
- Each escalation triggers WhatsApp/SMS to next level
